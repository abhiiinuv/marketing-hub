Executions are records of agent work inside an Epic. They help you understand what was handed off, which agent ran, what changed, and what still needs attention.

## What an Execution Tracks

An execution can include:

- the initiating prompt or handoff
- selected specs and tickets
- target agent
- status
- changed files
- review findings
- verification notes
- follow-up actions

## Why It Matters

Without execution tracking, multi-agent work becomes hard to audit. You can see that code changed, but not which agent made which decision or which context it used.

Executions preserve the chain of work so future agents and humans can continue from the same record.

## Use Executions For

- reviewing implementation history
- deciding whether to hand off to another model
- finding incomplete tickets
- checking whether review findings were addressed
- understanding why a change was made
