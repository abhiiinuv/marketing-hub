An Epic is a persistent workspace for a project-sized unit of AI development. Use it when a task has enough moving parts that one chat will become hard to manage.

## Create an Epic

<Steps>
  <Step title="Start from intent">
    Describe the outcome you want: a feature, refactor, bug fix, review, or investigation.
  </Step>
  <Step title="Capture project context">
    Add the relevant repository, files, specs, constraints, and existing decisions.
  </Step>
  <Step title="Create specs and tickets">
    Let Traycer help break the work into focused specs and implementation tickets.
  </Step>
  <Step title="Open agent tabs">
    Create GUI chats or terminal agents inside the Epic. Each tab can use the Epic context.
  </Step>
  <Step title="Review the result">
    Use diffs, review artifacts, and verification prompts to keep implementation aligned with the captured intent.
  </Step>
</Steps>

## What Belongs in an Epic

- requirements and acceptance criteria
- technical constraints
- architecture decisions
- tickets and implementation slices
- design notes
- agent conversations
- review findings
- diffs and changed-file context

## When to Stay in Regular Mode

Stay in Regular Mode when the work is small, local, and easy to complete in one focused conversation.
